심각 Kinetic energy explosion (100x in 2.001E-04s)
운동 에너지가 2.001E-04초 동안 18096배 증가했습니다 (KE: 1.838E-03 → 3.326E+01). 운동 에너지 KE = Σ(½mv²)가 급격히 증가한다는 것은 일부 노드의 속도가 발산(velocity divergence)했다는 의미입니다. 명시적 적분에서 v(t+dt) = v(t) + (F/m)×dt로 업데이트하는데, F가 비정상적으로 크면(contact spike, constraint conflict) 한 스텝에서 속도가 급증하고, 이 노드가 인접 요소를 왜곡시켜 추가적인 penalty force를 생성하는 양성 피드백 루프가 형성됩니다. 100배 이상의 KE 증가는 시뮬레이션이 발산 단계에 진입했음을 나타내며, 이후 NaN 또는 negative volume 에러로 이어집니다.
→ 1. 발산 시점(t=1.929E-05s) 전후의 변형 확인 — 애니메이션에서 비정상적으로 빠르게 움직이는 노드/파트 식별 2. Constraint 정의 점검 — *CONSTRAINED_EXTRA_NODES, *CONSTRAINED_RIGID_BODIES 등에서 과잉 구속 확인. 같은 노드에 여러 구속이 적용되면 내부적으로 상반되는 힘이 생성 3. 접촉 초기 관통 제거 — 관통된 노드에 과도한 penalty force가 집중되어 속도 발산의 주요 원인. *CONTROL_CONTACT의 PENOPT 설정 4. Penalty stiffness 감소 — SLSFAC < 0.1로 설정하여 접촉력 크기를 완화. SOFT=1(segment-based) 사용 권장
심각 Segmentation fault (Signal 11)
LS-DYNA 프로세스가 Segmentation fault (Signal 11)로 비정상 종료되었습니다. Slurm job 21393, 노드: node001. Segmentation fault는 프로세스가 할당되지 않은 메모리 영역에 접근할 때 OS가 보내는 SIGSEGV(Signal 11) 신호입니다. LS-DYNA에서 이는 주로: (1) 메모리 부족으로 배열 경계를 초과한 접근, (2) 극심한 요소 왜곡으로 내부 데이터 구조가 손상, (3) NaN 전파로 인덱싱 연산이 비정상적 메모리 주소 참조, (4) MPI 도메인 분해에서 프로세서 간 데이터 불일치 등으로 발생합니다. d3hsp 파일이 불완전하게 종료된 경우(termination message 없음), 이 segfault가 종료 원인입니다.
→ 1. 메모리 증가 — LS-DYNA 입력에서 memory=4000m 등으로 메모리 할당 증가. 메모리 부족이 가장 흔한 segfault 원인 2. d3hsp 분석 — d3hsp 파일의 마지막 경고/에러 메시지 확인. segfault 직전에 negative volume, NaN 등의 경고가 있었을 수 있음 3. 요소 erosion 설정 — 요소 왜곡에 의한 메모리 손상 방지를 위해 *MAT_ADD_EROSION 또는 *CONTROL_TIMESTEP ERODE=1 설정 4. 접촉 설정 완화 — penalty stiffness 감소, SOFT=1 사용, 초기 관통 제거로 극심한 왜곡 방지 5. Double precision 사용 — SP(single precision)에서 DP로 전환하면 부동소수점 overflow에 의한 비정상 메모리 접근 방지

Penalty 기반 접촉에서 접촉 강성(contact stiffness)은 k = (fs × K × A²) / V로 계산되며, 이 강성이 높을수록 접촉 안정성 dt가 작아집니다. 접촉 dt가 요소 dt보다 작으면 접촉이 전체 시뮬레이션의 timestep을 지배합니다.
